# 《卡卡教你学AI》完整开发说明（给 Codex）

> 本说明**自包含**，请从零开始开发一个完整项目，不要依赖任何外部仓库或文件。

## 一、项目概述

- **游戏名**：《卡卡教你学AI》
- **定位**：让 AI 新手小白**边玩边学 AI** 的 3D 闯关游戏
- **一句话**：在「AI 世界」里闯关，从「完全不懂」成长为「AI 达人」，全程有陪伴助手卡卡陪着
- **目标用户**：想学 AI、但零基础或入门级的新手小白
- **核心价值**：用游戏化（闯关/地图/养成）降低学习门槛；用陪伴助手（对话/求助/亲密度）提升留存；用真实实操（真调 LLM、vibecoding）保证「真的学会」

## 二、技术栈（必须用这些，不要换）

| 类别 | 技术 |
|---|---|
| 语言/框架 | TypeScript + Vite |
| 3D 引擎 | Three.js（3D 场景 + 卡通渲染 toon shading） |
| LLM | DeepSeek API（用户提供 key） |
| 后端代理 | Vite dev proxy / Vercel Serverless Function（隐藏 API key） |
| 数据 | localStorage（MVP 存档/埋点） |
| 部署 | GitHub Pages / Vercel |
| 3D 资产 | 程序化几何体优先 + 免费 CC0 资产（Kenney.nl / Poly Pizza / Quaternius） |

**DeepSeek 接入细节（重要，避免踩坑）**：
- DeepSeek 兼容 OpenAI API 格式：`base_url = https://api.deepseek.com`，`model = "deepseek-chat"`
- **API key 绝不能写进前端代码**，必须走后端代理（Vite dev proxy 或 Vercel Serverless Function，key 放环境变量）
- **DeepSeek 没有 embedding 接口**，RAG 需要另选中文 embedding（如 bge-m3），MVP 阶段可先用「关键词/规则检索」跑通，完整版再接真向量

## 三、产品需求

### 3.1 世界观与学习板块（5 岛）

一个漂浮的「AI 世界」，5 座主题岛屿环绕中心广场。玩家空降中心广场，逐岛闯关，通关全部 5 岛 = 成为 AI 达人。

| # | 岛名 | 学什么 | 核心内容 | MVP |
|---|---|---|---|---|
| 1 | 认识之岛 | AI 是什么 | AI 基础概念 + AI 产品认知 | ✅ |
| 2 | 理解之岛 | AI 怎么运作 | 大模型原理、Token、幻觉、温度、memory、RAG | ✅ |
| 3 | 使用之岛 | 怎么用 AI | 提示词工程、AI 实操、vibecoding | ✅ |
| 4 | 进阶之岛 | 怎么让 AI 干活 | Agent、工具调用、MCP、工作流 | 后续 |
| 5 | 责任之岛 | 怎么安全负责地用 | 成本、提示注入、边界、核实 | 后续 |

**递进线**：认识 → 理解 → 使用 → 进阶 → 责任（小白 → 达人）。

### 3.2 核心玩法循环

```
探索 3D 地图 → 进入关卡（问答 / 任务）→ 卡壳时求助卡卡（耗次数）
→ 通关获得「知识点 + 星星」→ 解锁下一关 / 下一座岛
→ 星星兑换求助次数 / 给卡卡装扮 → 亲密度上升 → 卡卡解锁新互动
```

### 3.3 关卡系统

**难度第一原则**：小白友好 ≠ 简单到不用动脑。题目用**生活化场景 + 大白话**出题；**术语后置**（通关后用小贴士揭示术语，如「老实 vs 大胆」→ 温度）。

**5 种关卡类型**：

| 类型 | 形式 | 判定方式 |
|---|---|---|
| 问答·单选 | 生活化场景选择题 | 规则：选项比对 |
| 问答·情境判断 | 给出场景做判断 | 规则：选项比对 |
| 任务·提示词拼装 | 把要素卡片拖到正确位置 | 规则：要素 + 顺序校验 |
| 任务·真实调 AI | 玩家写提示词 → 真调 DeepSeek → 检查结果 | 规则为主 + LLM 辅助 |
| 任务·Vibe Coding | 玩家写提示词 → 生成代码 → iframe 预览 | 规则（预览验证） |

**MVP 关卡清单（10 关）**：

| 岛 | 关卡 | 类型 | 学什么 |
|---|---|---|---|
| 认识之岛 | 1. 哪些是 AI 做的？ | 情境判断 | 生成式 AI 能做什么 |
| | 2. 生成式 AI 的边界 | 单选 | AI 不擅长实时事实 |
| | 3. 认识身边的 AI 产品 | 单选 | AI 产品分类（可灵/即梦/豆包/CodeBuddy） |
| 理解之岛 | 4. 为什么 AI 会胡说八道？ | 单选 | 幻觉 |
| | 5. 让 AI 更老实还是更大胆？ | 情境判断 | 温度（temperature） |
| | 6. AI 的「计费积木」 | 单选 | Token |
| 使用之岛 | 7. 提示词缺了什么？ | 单选 | 提示词四部件 |
| | 8. 拼出正确的提示词 | 提示词拼装 | 提示词结构 |
| | 9. 亲手写一句广告语 | 真实调 AI | 真实调用 LLM 完成任务 |
| | 10. 我的第一个 AI 作品 | Vibe Coding | 让 AI 生成一个变色按钮 |

### 3.4 陪伴助手「卡卡」

**人设**：刀子嘴豆腐心的**老师陪伴角色**。刀子嘴=毒舌、爱吐槽、说重话；豆腐心=内心柔软、真心为你好、护短。**所有毒舌最终都指向「我想让你真的学会」**。

**口癖（绑定情绪）**：

| 情绪 | 口癖 |
|---|---|
| 毒舌/傲娇 | 「这都不会吗？」「……算了，我教你」「哼，算你过关」 |
| 开心 | 「不错嘛」「有两下子」 |
| 无奈 | 「我再讲一遍，就一遍」 |
| 担心 | 「喂，别逞强」「……别熬了」 |

**亲密度四档**：

| 亲密度 | 等级 | 说话方式 |
|---|---|---|
| 0–100 | 初识 | 高冷惜字：「有问题问，没事别吵我」 |
| 100–300 | 熟悉 | 毒舌吐槽但认真教 |
| 300–600 | 亲密 | 护短：「谁说你笨？你是我带出来的」 |
| 600+ | 家人 | 毒舌藏关心：「别熬夜刷题了……我会担心的」 |

**求助机制**：有次数限制；分级响应「提示 → 思路 → 答案」（不直接喂答案）；次数来自每日赠送 + 通关奖励 + 聊天涨亲密度解锁。

### 3.5 画风（蛋仔派对风）

- Q 版、圆润、无尖角、软萌
- 明亮糖果色、柔和高饱和
- 卡通渲染（toon shading）、柔和光照、流畅动效
- **非像素风**
- **不要用色调映射**（ACESFilmic 等会压暗降饱和），保持颜色明亮
- 立体感靠「强方向光 + 弱环境光」制造明暗对比，而非后期处理

### 3.6 AI 技术方案

**架构原则**：**能规则就规则，该 LLM 才 LLM**（确定性内核 + LLM 智能外壳）。

**调用 LLM 的地方（6 处）**：卡卡闲聊、卡卡求助（分级）、真实调 AI 任务、Vibe Coding 任务、开放式问答评判、知识问答（RAG 生成）。

**不调用 LLM（用规则/传统手段）**：选择题判定（选项比对）、提示词拼装判定（要素+顺序校验）、亲密度/数值计算、成长解锁逻辑、求助次数扣减、存档（localStorage）、UI 状态机、RAG 检索（embedding + 余弦相似度）。

**兜底策略（防幻觉 + 防失败）**：
- 「宁可不答，也不错答」+「AI 失败优雅降级到规则」
- 知识问答：只答知识库检索到的内容，检索不到就说「这个我还在学」
- LLM 调用失败：降级到预设规则对白库
- 生成代码报错：不判失败，提示「让 AI 自己修」→ 变成教学点
- 提示词注入：输入过滤
- 成本失控：限时、失败最多重试 1~2 次、记 token

### 3.7 埋点设计

| 类别 | 事件 | 字段 |
|---|---|---|
| 学习效果 | level_answer 作答 | 关卡/题目ID、选项、对错、是否求助、用时 |
| | level_complete 通关 | 关卡ID、得分、求助次数、失败次数、用时 |
| 对话/助手 | chat_send / assistant_reply | 消息类型、是否走LLM、延迟、token、是否降级 |
| | help_escalate 求助升级 | 走到提示/思路/答案哪一级 |
| 留存/陪伴 | session_start / session_end | 时长、距上次间隔 |
| | intimacy_change 亲密度 | 来源、数值 |
| 产品/性能 | llm_call | 用途、token、耗时、成败 |

MVP：前端埋点 → 本地存储 → 可视化数据看板（亲密度曲线、答对率、求助率）。

### 3.8 RAG 知识库与评测集（贯穿线，不是最后才做）

- **RAG 知识库**：随关卡开发同步沉淀（认识岛关卡做完 → 沉淀第 1 岛知识点；理解+使用岛做完 → 补全三岛知识库；接入 LLM 时实现检索）
- **评测集**：① 对话质量评测集（考卡卡，验证人设/情绪/亲密度）② 学习效果评测集（关卡判定/答对率）。上线前跑一遍自测，上线后用埋点真实数据迭代。

## 七、关键约束（务必遵守）

1. **每次行动前先给出方案，确认后再动手**（尤其涉及画风、难度、交互的重大改动）。
2. **每完成一个功能块 commit 一次**，commit message 用 `feat:/fix:/docs:/chore:` 前缀。
3. 关卡难度要「看得懂 + 需要理解概念才能答对」，用生活化场景 + 术语后置。
4. 教育内容准确性是生命线，知识库内容要「宁可不答也不错答」。
5. 3D 性能注意：低多边形、控制面数、按需渲染。
6. 画风是后面所有关卡的地基，M1 画风必须验收通过再往下做。
