# 项目行动计划（PLAN）· 卡卡教你学AI

> 本文档是开发期的**执行计划**，实际开发严格按此推进。对应 PRD 的迭代版本（v0.x）。

---

## 1. 项目总览

- **目标**：做出一个可运行、可演示、可部署的「AI 学习闯关游戏」MVP，再迭代到完整版。
- **范围**：5 座岛 + 陪伴助手卡卡 + 3D 探索世界 + 数据看板。
- **北极星**：玩家是否真的学会了（首次答对率 + 通关率）。

---

## 2. 技术栈与工具清单

| 类别 | 工具 | 用途 |
|---|---|---|
| 语言/框架 | **TypeScript + Vite** | 前端工程、模块化 |
| 3D 引擎 | **Three.js** | 3D 世界、角色移动、卡通渲染 |
| LLM | **DeepSeek API** | 卡卡对话、求助、实操任务生成 |
| 后端代理 | Vite dev proxy / Vercel Serverless Function | 隐藏 API key、转发 LLM 请求 |
| 3D 资产 | Kenney.nl / Poly Pizza / Quaternius（CC0） | 免费 low-poly 模型 |
| 3D 生成 | Meshy / Tripo / 腾讯混元3D | 生成卡卡与主角专属形象 |
| 数据 | localStorage → IndexedDB（MVP） | 存档、埋点数据 |
| 向量检索 | MVP：规则/关键词检索 → 完整版：中文 embedding（bge-m3） | RAG 知识库检索（**DeepSeek 无 embedding 接口，需另选**） |
| 版本管理 | Git + GitHub（Averymeng/Game） | 全程同步进度 |
| 开发辅助 | Claude Code（AI 编程） | vibe coding 开发 |
| 部署 | GitHub Pages / Vercel | 静态站点上线 |
| 测试 | vitest（可选） | 关卡判定逻辑单测 |

## 7. 协作与 git 约定

- **每次行动前先对齐**：先给「步骤清单 + 方案」→ 用户确认 → 才执行。
- **每完成一个里程碑/功能块，立即 commit + push**（不攒着）。
- **commit message 规范**：`feat: 功能 / docs: 文档 / fix: 修复 / chore: 杂项`。
- **验收节奏**：每个里程碑做完，让用户玩一遍验收（难度、画风、功能）。

---

## 8. 验收标准

| 维度 | 标准 |
|---|---|
| 难度 | 目标用户（小白）看得懂、但要「想一下」；秒答=太简单，要加难度 |
| 画风 | 蛋仔派对风（Q 版圆润、糖果色、非像素） |
| 陪伴感 | 卡卡「刀子嘴豆腐心」人设立得住，毒舌最终指向「想让你学会」 |
| 功能 | 能跑、能玩、求助/亲密度/闯关闭环通顺 |
| 学习效果 | 通关后有「真的学到了」的感觉（小贴士揭示术语） |

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 3D 性能卡顿 | 控制模型面数、低多边形、按需渲染 |
| LLM 成本 | 规则层 0 成本、限频、记 token、分级求助不每次都调 LLM |
| 内容准确性（幻觉） | RAG 只答库内 + 「宁可不答也不错答」+ 人工质检 |
| API key 泄漏 | 后端代理，key 放环境变量，不进前端 |
| 关卡难度失衡 | 埋点看求助率/答对率，数据驱动调题 |
| 3D 建模不足 | 先用程序化几何体，再补免费资产 + AI 3D 生成 |
