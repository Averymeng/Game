# PRD · 《卡卡教你学AI》

> 一个让 AI 新手小白边玩边学 AI 的 3D 闯关游戏，内置刀子嘴豆腐心的陪伴助手「卡卡」。
> 文档版本：v0.1（方案定稿版）｜ 状态：待开发

---

## 1. 产品概述

### 1.1 一句话定位

**让小白在「AI 世界」里闯关，从「完全不懂」成长为「AI 达人」，全程有陪伴助手卡卡陪着。**

### 1.2 目标用户

- 想学 AI、但零基础或入门级的新手小白；
- 有学习意愿，但觉得「刷教程枯燥、刷短视频零散」的人；
- 需要「游戏化 + 陪伴式」降低学习门槛的人。

### 1.3 核心价值（应用价值）

解决真实痛点：**AI 知识焦虑**——人人想学 AI，但传统学习方式门槛高、留存低。

- 用**游戏化**（闯关、地图、养成）降低学习门槛；
- 用**陪伴助手**（对话、求助、亲密度）提升学习留存；
- 用**真实实操**（真调 LLM、vibecoding）保证「真的学会」，而非「玩个热闹」。

### 1.4 北极星指标

**「玩家是否真的学会了」** —— 由两个可量化指标支撑：

- **首次答对率**（衡量「学到了」）；
- **通关率**（衡量「学完了」）。

辅助指标：次日留存、求助率、亲密度增长。

---

## 2. 世界观与叙事

- **世界观**：一个漂浮的「AI 世界」，由 5 座主题岛屿组成，每座岛对应一个 AI 学习板块。
- **玩家**：空降中心广场的新手小白。
- **成长线**：逐岛闯关，从「认识 AI」一路到「懂边界」，**通关全部 5 座岛 = 成为 AI 达人**。

---

## 3. 学习板块规划（5 岛白话递进）

**规划思路**：按「小白学习阶段」白话递进切分，把「原理类」内容（大模型、memory、RAG 等）归拢到「理解」岛，不刻意细分。

| # | 岛名 | 学什么 | 核心内容 | MVP |
|---|---|---|---|---|
| 1 | 🏝️ 认识之岛 | AI 是什么 | AI 基础概念 + **AI 产品认知**（可灵/即梦/豆包/CodeBuddy/WorkBuddy 等分类与同类比较） | ✅ |
| 2 | 🧬 理解之岛 | AI 怎么运作 | 大模型原理、训练 vs 推理、Token、幻觉、温度、**记忆 memory、RAG、上下文** | ✅ |
| 3 | 🛠️ 使用之岛 | 怎么用 AI | 提示词工程、AI 产品实操、vibecoding | ✅ |
| 4 | 🤖 进阶之岛 | 怎么让 AI 干活 | Agent、工具调用、MCP、工作流 | 后续 |
| 5 | ⚖️ 责任之岛 | 怎么安全负责地用 | 成本计费、提示注入、边界、核实 AI 回答 | 后续 |

**递进线**：认识 → 理解 → 使用 → 进阶 → 责任，即「小白 → 达人」。

**澄清**：进阶之岛 = 「让 AI 自动干活」（达人进阶技能），**不是**「学做 AI 产品」。「学做 AI 产品」作为**通关后隐藏番外篇**（不进主线）。

---

## 4. 核心玩法循环

```
探索 3D 地图 → 进入关卡（问答 / 任务）→ 卡壳时求助卡卡（耗次数）
→ 通关获得「知识点 + 星星」→ 解锁下一关 / 下一座岛
→ 星星兑换求助次数 / 给卡卡装扮 → 亲密度上升 → 卡卡解锁新互动
```

**关键打通**：把「求助次数」和「陪伴亲密度」串成一条线——聊天涨亲密度，亲密度高了解锁额外求助或更给力的帮助。

## 5. 关卡系统设计

### 5.1 难度第一原则

> **小白友好 ≠ 简单到不用动脑。** 玩家是 AI 小白，但不是傻子。

- 题目用**生活化场景 + 大白话**出题；
- **术语后置**：通关后用小贴士揭示背后的术语（如「老实 vs 大胆」→ 温度）。

### 5.2 关卡类型（5 种）

| 类型 | 形式 | 判定方式 |
|---|---|---|
| 问答·单选 | 生活化场景选择题 | 规则：选项比对 |
| 问答·情境判断 | 给出场景做判断 | 规则：选项比对 |
| 任务·提示词拼装 | 把要素卡片拖到正确位置 | 规则：要素 + 顺序校验 |
| 任务·真实调 AI | 玩家写提示词 → 真调 deepseek → 检查结果 | 规则为主 + LLM 辅助 |
| 任务·Vibe Coding | 玩家写提示词 → 生成代码 → 游戏内 iframe 预览 | 规则（预览验证）|

### 5.3 关卡清单（MVP）

| 岛 | 关卡 | 类型 | 学什么 |
|---|---|---|---|
| 认识之岛 | 1. 哪些是 AI 做的？ | 情境判断 | 生成式 AI 能做什么 |
| | 2. 生成式 AI 的边界 | 单选 | AI 不擅长实时事实 |
| | 3. 认识身边的 AI 产品 | 单选 | AI 产品分类（可灵/即梦/豆包/CodeBuddy） |
| 理解之岛 | 4. 为什么 AI 会胡说八道？ | 单选 | 幻觉 |
| | 5. 让 AI 更老实还是更大胆？ | 情境判断 | 温度（temperature） |
| | 6. AI 的「计费积木」 | 单选 | Token |
| 使用之岛 | 7. 提示词缺了什么？ | 单选 | 提示词四部件 |
| | 8. 拼出正确的提示词 | 提示词拼装 | 提示词结构 |
| | 9. 亲手写一句广告语 | 真实调 AI | 真实调用 LLM 完成任务 |
| | 10. 我的第一个 AI 作品 | Vibe Coding | 亲手让 AI 生成一个变色按钮 |

## 6. 陪伴助手「卡卡」设计

### 6.1 人设卡

| 维度 | 设定 |
|---|---|
| 名字 | 卡卡 |
| 定位 | AI 世界向导 / **刀子嘴豆腐心的老师陪伴角色** |
| 核心性格 | **刀子嘴**：毒舌、爱吐槽、会说重话；**豆腐心**：内心柔软、真心为你好、会心疼你、护短 |
| 反差落点 | 所有的毒舌，最终都指向一件事——**「我想让你真的学会」** |

### 6.2 口癖（绑定情绪）

| 情绪 | 口癖 |
|---|---|
| 毒舌/傲娇 | 「这都不会吗？」「……算了，我教你」「哼，算你过关」 |
| 开心 | 「不错嘛」「有两下子」 |
| 无奈 | 「我再讲一遍，就一遍」 |
| 担心 | 「喂，别逞强」「……别熬了」 |

### 6.3 亲疏关系（亲密度四档）

| 亲密度 | 等级 | 说话方式 |
|---|---|---|
| 0–100 | 初识 | 高冷惜字：「有问题问，没事别吵我」 |
| 100–300 | 熟悉 | 毒舌吐槽但认真教 |
| 300–600 | 亲密 | 开始护短：「谁说你笨？你是我带出来的」 |
| 600+ | 家人 | 句句毒舌藏着关心：「别熬夜刷题了……我会担心的」 |

### 6.4 求助机制（分级响应 + 次数限制）

- 求助**有次数限制**（逼玩家先自己想，别当抄答案工具）；
- 次数获取：每日赠送 + 通关奖励 + 聊天涨亲密度解锁额外次数；
- **分级响应**：先给「提示」→ 给「思路」→ 最后才给「答案」（像真老师，不直接喂答案）。

## 7. 3D 世界设计

- **中心广场**（出生点）：卡卡在此迎接玩家。
- **5 座岛**：围绕广场分布，走近有传送门/关卡入口。
- **解锁可视化**：未解锁的岛灰暗/云雾，解锁后亮起，营造「点亮世界」的成就感。
- **地图彩蛋**：可收集的知识点光球、隐藏互动。

### 画风方向（蛋仔派对风）

- Q 版、圆润、无尖角、软萌；
- 明亮糖果色、柔和高饱和；
- 卡通渲染（toon shading）、柔光、流畅动效；
- **非像素风**。

### 建模方案

1. **程序化生成**：代码生成 low-poly 场景（岛屿、云、粒子）；
2. **免费资产**：Kenney.nl / Poly Pizza / Quaternius（CC0 授权）；
3. **AI 3D 生成**：Meshy / Tripo / 腾讯混元3D 生成主角与卡卡专属形象（注意授权）。

## 8. AI 项目技术方案

### 8.1 架构原则

> **能规则就规则，该 LLM 才 LLM。** 游戏骨架确定性优先，LLM 只用在「需要智能」的地方。

### 8.2 调用 AI 的地方（LLM / deepseek）

| 场景 | 用途 |
|---|---|
| 卡卡闲聊 | 生成有卡卡人设的回复 |
| 卡卡求助（分级） | 生成「提示→思路→答案」 |
| 真实调 AI 任务 | 玩家写提示词 → 生成结果 |
| Vibe Coding 任务 | 玩家写提示词 → 生成代码 |
| 开放式问答评判 | LLM 辅助判断语义 |
| 知识问答（RAG 生成） | 把知识组织成卡卡的说话方式 |

### 8.3 不调用 AI 的地方（规则 / 传统手段）

| 场景 | 手段 |
|---|---|
| 选择题/判断题判定 | 选项比对 |
| 提示词拼装判定 | 要素关键词 + 顺序校验 |
| 亲密度/数值计算 | 算术 + 阈值 |
| 成长/解锁逻辑 | 状态机 + 条件判断 |
| 求助次数扣减 | 计数器 |
| 存档 | localStorage 序列化 |
| UI 状态机/动画 | 前端状态机 |
| RAG 检索 | embedding + 余弦相似度（传统算法） |

### 8.4 RAG 与 Memory

- **RAG 知识库**：5 岛知识点 + 题库 + 解析，向量化存储，供卡卡检索回答。
- **Memory**：短期=当前对话上下文；长期=玩家画像（学过什么、卡在哪、偏好）+ 亲密度。

### 8.5 兜底策略（防幻觉 + 防失败）

> 核心两条：**「宁可不答，也不错答」+「AI 失败优雅降级到规则」**。

| 风险 | 兜底 |
|---|---|
| 知识问答幻觉 | 只答知识库检索到的内容；检索不到就「这个我还在学」；system prompt 写死「只基于资料回答」 |
| LLM 调用失败 | 降级到预设规则对白库 |
| 返回格式不对 | 重试 1 次 → 仍不对 → 规则兜底 |
| 任务判定不稳 | 结构化规则为主，LLM 辅助，失败降级纯规则 |
| 生成代码报错 | 不判失败，提示「让 AI 自己修」→ 变成教学点 |
| 提示词注入 | 输入过滤处理 |
| 成本失控 | 限时、失败最多重试 1~2 次、记 token |

### 8.6 成本控制

规则层 0 成本；LLM 仅用于 6 个智能场景；缓存 + 限频 + 分级求助（不每次都调 LLM）；所有 LLM 调用记 token。

## 9. 评测方案

**区分**：RAG 是「功能」（运行时让 AI 查资料回答）；评测是「把关」（答得好不好）。

### 9.1 三层评测

| 层 | 内容 |
|---|---|
| 对话质量 | 人设一致性 / 情绪匹配 / 亲密度匹配 / 陪伴价值 |
| 学习效果 | 答对率、求助率、知识点掌握度、重复错误率 |
| 产品指标 | 通关率、留存、求助次数使用率、关卡时长 |

### 9.2 时间节点（两段）

| 时间点 | 做什么 |
|---|---|
| ① 开发期（上线前） | 拿测试题「考卡卡」，看对话质量/判定准确率，调 prompt/知识库 |
| ② 运营期（上线后） | 埋点收集真实数据 → 分析 → 迭代 |

## 10. 埋点设计

### 10.1 埋点事件表

| 类别 | 事件 | 字段 |
|---|---|---|
| 学习效果 | `level_answer` 作答 | 关卡/题目 ID、选项、对错、是否求助、用时 |
| | `level_complete` 通关 | 关卡 ID、得分、求助次数、失败次数、用时 |
| | `retry_answer` 重答 | 第几次错、是否同题 |
| 对话/助手 | `chat_send` / `assistant_reply` | 消息类型、是否走 LLM、延迟、token、是否降级 |
| | `help_escalate` 求助升级 | 走到提示/思路/答案哪一级 |
| 留存/陪伴 | `session_start` / `session_end` | 时长、距上次间隔 |
| | `intimacy_change` 亲密度 | 来源、数值 |
| 产品/性能 | `llm_call` LLM 调用 | 用途、token、耗时、成败 |
| | `error_event` 异常 | 类型、位置 |

### 10.2 数据 → 迭代闭环

| 数据信号 | 诊断 | 动作 |
|---|---|---|
| 某关求助率 80% | 太难/讲解不清 | 改题/改解析 |
| 某题重答仍错 | 解析没讲明白 | 重写解析 |
| 卡卡聊天后留存高 | 陪伴有效 | 加强陪伴 |
| LLM 失败率 5% | 兜底是否生效 | 优化降级 |
| 求助多走到「答案」级 | 分级太松 | 收紧分级 |

### 10.3 落地点

MVP：前端埋点 → 本地存储 → 可视化数据看板（亲密度曲线、答对率、求助率）。

## 11. 内容生产流程（AI 生成 + 人工质检）

| 内容 | 谁做 | 说明 |
|---|---|---|
| RAG 知识库（知识点/题库/解析） | 我生成初稿 → **用户审核校对** → 定稿入库 | 教育内容准确性是生命线，必须人工把关 |
| 对话质量评测集 | 评测标准我设计；样本我出初稿、共同定 ground truth | 一起定标准答案 |
| 任务判定规则 | 我设计 → 跑测试用例验证 | 用户抽查 |
| 学习效果/产品指标 | 运行时自动产生 | 不用提前做 |

## 12. MVP 范围 vs 完整版

## 13. 迭代规划

1. **v0.1**：PRD 定稿（本文档）。
2. **v0.2**：项目骨架 + 认识之岛 1~2 关 + 卡卡基础对话（验收难度与画风）。
3. **v0.3**：MVP 三岛全部关卡 + 求助机制 + 数据看板。

5. **v1.0**：完整版（5 岛）+ 部署上线。
